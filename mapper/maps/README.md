# Готові карти

Сюди редактор сам кладе кожну карту: через 20 с тиші після останньої правки,
одразу після експорту PNG і при закритті вкладки. Робить це `/api/maps`
(`functions/api/maps/`) через GitHub Contents API — див. «Архів готових карт»
у DEPLOY.md.

Раніше редактор тримав роботу лише в браузері: ключ `tgmine-map` у
localStorage, один слот, перезапис раз на 1.5 с. Наступна ніч затирала
попередню, очищення сайту стирало все. localStorage лишився страховкою на
поточну секунду, а архів — тут.

Формат — той самий, що дає «Експорт → map.json» у редакторі; повертається
через «Імпорт». Файл самодостатній: обʼєкти, зони, види, вид камери, стиль,
легенда, підпис.

- `2026-09-03-nichnyi-nalit.png` — експорт ночі на 3 вересня 2026 (1832×1643),
  єдиний збережений рендер; вихідного JSON до нього не лишилось.
- `2026-08-24-nichnyi-nalit.json` — ніч на 24 серпня 2026, 39 обʼєктів. Дістано
  з тіней leveldb локального сховища Chrome (localhost:8765), перевірено
  імпортом.
- `2026-09-13-nichnyi-nalit.json` — ніч на 13 вересня 2026, 26 обʼєктів,
  5 зон, 10 видів. Витягнуто з автозбереження браузера 16 вересня 2026;
  перевірено імпортом у редактор (26 обʼєктів, 5 зон, 10 видів на місці).

Іменування: `РРРР-ММ-ДД-назва.json` за датою карти, не за датою збереження.

## Хто може писати у файл сам (з 1 жовтня 2026)

Автозбереження пише лише у файл, який цей браузер сам створив, відкрив із
сервера або свідомо замінив, — і лише поки це та сама робота. Інакше воно
стоїть і каже чому (рядок під кнопками, позначка «на сервер не йде» в HUD);
кнопка «Зберегти зараз» пише завжди, а якщо замінює чуже чи давнє — питає.

Причина: файл зветься за ніччю з ПІДЗАГОЛОВКА, один на всіх користувачів, а
сервер на розбіжність sha перечитував файл і писав поверх. Аудит історії цієї
теки знайшов 12 затертих карт із 19, трьома способами:

1. **чужий екран** — у власника підзаголовок завис на «ніч на 26 вересня»
   (сам він оновлюється лише в «Покласти збиття / ППО»), і його екран щодня
   лягав у карту оператора за 26-те; 24.09 двоє писали в один файл по черзі;
2. **наступний ранок** — браузер відновлює вчорашню карту, оператор стирає
   її, щоб почати нову, і напівстерта лягає поверх готової (17, 18, 19, 25,
   28 вересня);
3. **«прибрав усе, щоб глянути»** — готова карта стає порожньою підкладкою
   (20, 22, 23 вересня, 1 жовтня).

Правила (клієнт — `srvPush`/`srvFlush` у `editor.html`, сервер — `write` у
`functions/api/_store.js`):

- свого sha нема або він старший за 3 год -> лише створення; файл уже є ->
  409, автозбереження стоїть. Паузи між записами в справжній роботі: медіана
  3 хв, найбільша 41 хв; наступний ранок — це 22 години;
- **файл створюється, коли на карті є намальоване руками**, а не самі взяті
  з даних підказки (експорт PNG і кнопка кладуть одразу). Власник, зазирнувши
  зранку першим, тричі створював файл ночі (21, 23, 25 вересня) — без цього
  правила оператор цілий ранок писав би в зайняту назву. У оператора перший
  свій обʼєкт зʼявляється за 2–14 хв, у власника — ніколи;
- sha не збігається з файлом -> 409, крім запису після закриття вкладки:
  редактор приносить відбитки того, що тоді послав, і якщо у файлі лежить
  рівно це — то його ж запис. (Перша версія звіряла імʼя автора; одного
  логіна у двох браузерах вистачало б, щоб затерти свіжішу роботу.);
- обʼєктів стало менше половини від збереженого (при ≥10) АБО намальованих
  руками — менше половини (при ≥5) -> стоїть, доки не повернуться. У
  справжній роботі крок за загальним ліком не падав нижче 69%, а «руками» не
  зменшувалось ні разу; у затираннях — не вище 42%. «Руками» окремо, бо
  23.09 готову карту (41 обʼєкт, 24 руками) затерли 83 щойно взяті підказки;
- «Нова карта», інша ніч, «Прибрати все з ночі» -> файл більше не свій;
- карта з самої підкладки не йде взагалі;
- 409 від GitHub при тому самому sha (гілку посунув коміт CI) — повтор.

Кнопка «Зберегти зараз» пише завжди; якщо замінює — питає, і окремо
попереджає, коли на карті обʼєкти іншої ночі, ніж у підзаголовку.

**Перевірка відтворенням історії.** Усі 238 записів редактора з історії цієї
теки прогнано через правила по порядку: 16 із 16 карт оператора закінчуються
рівно на готовій версії (тій, що повернуто вручну за незалежним критерієм —
найбільше намальованого руками за ранок своєї ночі). Без правила «створення
лише з роботою» таких було 13 із 16: три ранки оператор був би заблокований.

Тести: `tests/js/store_write.mjs` (сервер, 19 випадків, у pytest) і
`tests/js/editor_srv_scenarios.js` (редактор у браузері, 47 сценаріїв; запуск
описано у файлі). Мутації обох наборів убиті (8 + 15), контроль зелений.

Затерті карти повернуто з історії 1 жовтня 2026 — версією з найбільшою
кількістю намальованого руками за ранок своєї ночі. Знайти таку знову:
`git log -- mapper/maps/<файл>` і лік обʼєктів по комітах.
